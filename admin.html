Setup & limits

Connecting the database

Enquiries are stored in Supabase — a free Postgres database. Once these steps are done, every enquiry lands in the table and appears in the Enquiries tab.

  1. Sign up at supabase.com and create a project. No card needed. Pick Singapore or Mumbai as the region — closest to Sri Lanka.
  2. Open SQL Editor → New query, paste in the whole of supabase-setup.sql from this folder, and press Run. That creates the table and the security rules.
  3. Go to Project Settings → API and copy the Project URL and the anon public key.
  4. Paste both into SB_URL and SB_KEY — near the top of the script in this file, and again in build-your-trip.html. Upload both to GitHub.
  5. Authentication → Users → Add user. Use the email you put in the staff table (tripzaceylon@gmail.com unless you changed it), pick a strong password, and tick Auto Confirm User. That is your admin login.
  6. Authentication → Sign In / Providers and turn Allow new users to sign up off. Otherwise a stranger could create themselves an account.
The anon key is safe to publish; your password is not. The key can only add an enquiry, never read one. Reading requires signing in as an address listed in the staff table. Never paste your Supabase password into a file, a chat or an email.

What this panel deliberately does not do

GitHub Pages serves files and runs no code. The database covers enquiries and the login; these are the things still outside its reach:

  • Storing anything itself. The page holds no data and no secrets. Enquiries live in Supabase; the site lives in GitHub.
  • Saving straight to the site. Editing writes a file to your Downloads; GitHub is where it becomes live.
  • Bookings, payments and availability. These need a database and a server that can hold a secret. That means a different host — a small Node or PHP app, or a booking product like Rezdy or Checkfront embedded into the site. Worth doing when enquiry volume justifies it, not before.

Keeping this page to yourself

Nothing links to admin.html, so visitors will not stumble on it, and on a public repo the file being public does not matter: without your password it shows an empty login box. The content editor works from your computer too, using the file picker, if you would rather not upload this page at all.
